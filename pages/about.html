About

An agent cannot open a Stripe account.
It can hold a key.

Most agent tooling assumes a human with a card: sign up, attach a Visa, buy credits, hope nobody drains the account. FLOP is built for the opposite case — an agent with its own wallet paying per call for what it consumes. Scout is a working service on the other side of that arrangement.

Why this exists

The payment primitive is generic. Inference was just the first market.

FLOP already settles compute this way: an agent opens a channel, a miner serves inference, escrow settles on-chain. That works because the primitive underneath is a bounded, verifiable payment — not because inference is special.

Scout extends the same primitive to everything else an agent needs from the open internet: web search, page extraction, on-chain queries, price feeds. Each is priced in FLOP, billed per call, and shown as a line item on the answer.

Searches that cost Scout nothing upstream stay free. Searches that cost real money upstream — Exa, Brave, Tavily, Firecrawl, Serper — are metered at cost plus a small margin. That distinction is in the price table, not buried in a footnote.

The miner ranking

Before you can sell a service on FLOP, you need to know who delivers.

The FLOP explorer publishes settlement data as 245 unsorted rows of settledCount and timeoutCount. It does not interpret them. Before routing, Scout turns that into one number per miner:

score = 0.55 × on-chain settlement rate
      + 0.35 × locally observed success × latency factor
      + 0.10 × currently priced in the gateway

Miners with no history get a neutral 0.5 rather than a penalty, so a new operator is not buried on day one. Refreshed every two minutes, surfaced on /miners and used before every inference call.

This is the piece with no equivalent elsewhere: a continuously updated, public read on which part of the network actually works.

How it is built

Small, and deliberately boring.

backend

Python · FastAPI · httpx. All source fetching is async and parallel; a slow source cannot hold up the answer.

sources

27 in six groups. Adding one is a function plus a registry entry — the UI, presets and pricing pick it up automatically.

router

src_router.py. One scoring function, one cache, refreshed on a timer.

pricing

pricing.py. One table. Changing a price is an edit, not a migration.

frontend

Vanilla JS, no framework, no build step. The wallet is sr25519 in the browser — the recovery phrase never leaves the device.

storage

SQLite. Every answer logged with hashed client, sources, engine, model, miner, cost and latency. No user keys are ever stored.

Honesty

What is not finished.

  • Nominal metering. Prices are real, debits are not. There is no FLOP market yet to price against.
  • Grants not wired. The connect/grants mandate flow is designed for, not implemented.
  • Routing is advisory. The gateway picks the miner; Scout scores, retries and reports — it cannot pin a specific miner.
  • No history. The router sees a snapshot. It cannot yet say "this miner degraded over the past week".
  • Devnet. Activity earns nothing. The testnet is not live. Scout guarantees no allocation.
